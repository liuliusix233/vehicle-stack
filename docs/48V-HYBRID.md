# 48V 轻混功率推算（估算模型）

> ⚠️ **这不是实测，是推算。** 车上没有 48V 母线电流传感器，我们只能用 OBD 能拿到的量
> （车速 / 转速 / 节气门 / 负荷 / SOC）去逼近真实功率。
>
> **精度：差。** 稳态趋势大致可信，瞬态和绝对值不可信；误差可能到几百瓦甚至更多。
> 只适合做「现在在助力还是在回收」的定性参考，**不要拿它做能量结算或保护逻辑**。

## 为什么做这个

VHAL 和 OBD 都拿不到 48V 系统的瞬时功率，但 HUD 上想显示一个「当前功率」的读数。
于是用物理模型先估一个基线，再用**唯一能观测到的真值锚点**——电池 SOC 跳格——去缓慢修正。

## 模型组成

```
总功率 = 助力(负) + 回收(正) + 维持充电(正) + 12V负载(负) + 修正项(±)
        ↓ 一阶低通 τ≈1.2s
      HUD 显示值
```

### 1. 轮上需求（物理基线）

```
P_wheel = m·a·v + 0.5·ρ·Cd·A·v³ + Crr·m·g·v
```

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `MASS` | 1900 kg | 整备质量（估） |
| `AERO` | 0.5·1.2·0.33·2.6 | ρ·Cd·A，Cd 0.33 / A 2.6 m² |
| `CRR` | 0.011 | 滚阻系数（估） |
| 加速度 | 逐帧差分，低通 0.25 | 限幅 ±4 m/s² |

### 2. 助力（assist，负功率）

```
assist = 8000W × 油门开度 × 转速就绪 × 需求因子 × SOC因子
```

- 油门开度：`(throttle-20)/60` 限幅 0–1（20% 以下不触发）
- 转速就绪：`(rpm-900)/1800` 限幅 0–1
- 需求因子：`0.35 + 0.65 × min(P_wheel/4000, 1)`
- SOC 因子：SOC ≤45% 时线性衰减，≤25% 归零
- 起步补丁：v<2 且油门>25% 且转速>700 → 至少 1500W 助力

### 3. 回收（regen，正功率）

```
regen = min((m·decel·v·0.62 + 220W×(v/10 上限3)) × SOC因子, 8000W)
```

- 只在油门 <8% 且车速 >3 m/s 时触发
- `ETA_REGEN = 0.62` 电机→电池效率（估）
- SOC ≥85% 时回收能力线性衰减到 0（满了收不进去）

### 4. 维持充电（maint）

转速 >650 且 SOC <50% 时最多补 400W，防止模型把电量算得一直往下掉。

### 5. 12V 负载（aux，负功率）

发动机转时 12V 系统由 48V 经 DCDC 供电，持续小放电：`-(110 + 40×min(v/10,2))` W。

### 6. SOC 跳格修正（trim）—— 唯一的真值锚点

这是整个模型里最诚实的部分：

- 电池 SOC 显示分辨率 **0.39%/格 ≈ 1.76Wh**（`PACK_WH=450`）
- 模型自己积分出「这段时间应该用掉多少 Wh」（`whSinceStep`）
- SOC 真的跳一格时，用实测差值结算误差：`trim += clamp(err×220, ±120)`
- trim 总量封顶 **±400W**，并以 τ≈40s 自然回零（防止自激振荡）
- 静止且 SOC 20 秒不动 → trim 加速收敛（此时真实功率必然接近 0）

## 误差从哪来（重要）

1. **没有电流传感器**——一切靠模型猜，这是根本限制。
2. 质量、风阻、滚阻都是估的，换轮胎/坐人/开空调都会变。
3. SOC 分辨率 0.39%，一格 1.76Wh，噪声比信号大。
4. 坡道没有进模型（HUD 有坡度读数，但没参与计算），上坡会系统性低估。
5. DCDC 效率、电池内阻温度特性都没建模。

## 怎么判断它还准不准

- **静止测试**：P 挡怠速 20 秒，读数应收敛到 0 附近（±100W 内）。
- **滑行测试**：60 km/h 松油门，读数应为正（回收）且随车速下降。
- **长时间校验**：把功率积分 30 分钟，和 SOC 实际下降对比，误差应在 ±10% 内；超了说明参数要重标。

## 结论

能用来做 HUD 上的一个动态数字，能看出「在助力 / 在回收」。
**不能**用来做电量结算、续航预测或任何保护动作。
