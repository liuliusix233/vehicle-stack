## 几个关键判断（这些比代码值钱）

### 1. 没有 ADB，就不要围绕 ADB 设计
车机是锁的。所有「adb push / adb install / adb shell」的方案在你车上直接死。
所以整个栈的地基是 **ShellBridge**：一个装在车机里的 App，自己开 TCP 7801，
把 adb 常用的能力（读文件、装 APK、启应用、读 VHAL、执行白名单命令）重新实现一遍。

### 2. 不要相信网上抄来的 VHAL ID
车机 `android.car.jar` 里定义的常量是 `ENGINE_RPM=0x11600305`、`PERF_VEHICLE_SPEED=0x11600209`，
和网上流传的 0x11600306 / 0x11600207 差 1~2。

**但要点是：常量存在 ≠ 能读到。** 本车 `ENGINE_RPM` 实测 `getFloatProperty` 返回 0.0、`getProperty` 返回 null，
而且它根本不在那 22 个已配置属性里——所以今天我们**没拿到任何转速数据**。

结论：ID 要从运行时枚举里取，不要从 jar 常量或网上资料推；枚举不到的就是没有。

### 3. 转速不要死磕 CAN/VHAL
我们试了 VHAL 直读、属性订阅、patacframework、PatacService、FSA 函数表，全空。
12 秒订阅 22 个属性 0 事件 —— 这台车根本没把 RPM 配进 VHAL。
结论：**买 80 块的蓝牙 OBD**，别浪费时间。

### 4. 屏幕用 Pi 直写 framebuffer，不要试图改原厂仪表
原厂仪表是 Kanzi 主题宿主 + 平台签名服务，第三方进不去（我们试过，`isClusterServiceReady=false`）。
外挂一块条屏 + fb0 直写，是成本最低、可控性最高的路。

### 5. 判断「车在不在跑」用电压，不用点火信号
点火信号要改线/读 VHAL 还不一定准；电压 13.2V 以上必然是发电机在工作。
实测：着车稳定 13.8–14.6V，熄火回落到 12.6V 左右，阈值放 13.2/13.0 很稳。

## 如果重来一遍，我会这样排期

1. **第 1 天**：确认车机能不能装第三方 APK（U 盘）。不能就别往下走。
2. **第 2–3 天**：装 ShellBridge，用 `#PING` 验证 TCP 通。这是所有自动化的前提。
3. **第 4–5 天**：`#CARALL` 枚举 VHAL，确认你要的数据在不在。
4. **第 2 周**：HUD（Pi + 屏），先把数据画出来，再谈美观。
5. **第 3 周**：电源 BLE + 自动 AC。
6. 停车监控买成品，别自研。
